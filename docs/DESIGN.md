# Clippy — Design Document

> *Your clipboard remembers enough to be useful, but forgets quickly enough to stay private.*
> Tagline: **Copy once. Find it again.**

Priorities, in order: Speed · Privacy · Simplicity · Native macOS · Keyboard-first · Reliability · AI usefulness.

---

## 1. Product analysis

Windows' Win+V works because the OS owns it. On macOS a third party has to (a) poll the pasteboard, (b) own a global hotkey, (c) synthesize a paste into another app. Everything good about Clippy comes from doing those three things *reliably*, and everything risky about it comes from the data it touches. So:

- **Capture is dumb, deterministic and cheap.** No AI, no network, no heavy work on the capture path.
- **Privacy is the product**, not a setting: the retention clock (24 h) and the sensitive-content filter are both on by default, and nothing is sent to a cloud without an explicit opt-in.
- **AI is strictly additive** and is never on the hot path. The app is fully useful with AI switched off.

### Product refinements I'm making to the brief

| Brief | Refinement |
|---|---|
| "Keep sensitive data in memory briefly" | Default is **drop entirely**. An opt-in "hold sensitive items in memory for 60 s" mode exists (so you can paste an OTP once), never touching disk. |
| Sensitive filter reliability | Layered: pasteboard *type hints* (`org.nspasteboard.ConcealedType`, `TransientType`, `AutoGeneratedType`) → source-app denylist → regex → entropy → context heuristics. The first layer is the most reliable and is what password managers actually emit. |
| Pinned items never expire | Agreed, but pinned items are **encrypted at rest** (see §8) since they're the long-lived ones. |
| "AI never silently extends retention" | Enforced structurally: the AI layer has **no write access** to `expires_at`. It can only *propose* (pin suggestion) or *delete early* (cleanup). |
| Image storage | Images live as files on disk (not DB blobs) with a thumbnail; there is a hard disk budget. |
| Cmd+K actions | Kept, plus `Tab` to switch Clipboard ⇄ Command mode, `⌘P` pin, `⌘⌫` delete, `⌘1…9` quick paste. |

## 2. macOS technical limitations (honest list)

| Area | Reality | How Clippy handles it |
|---|---|---|
| **Clipboard change notification** | `NSPasteboard` has **no change notification**. Only `changeCount` can be polled. | Poll `changeCount` on a timer (0.4 s, tolerance 0.2 s). Reading an `Int` is ~free; content is only read when the count changes. Timer is paused when monitoring is paused. |
| **Reading pasteboard on macOS 15.4+/26** | macOS added a pasteboard-access privacy prompt/alert for apps that read the pasteboard programmatically without user intent (`NSPasteboard.accessBehavior`, `detect` APIs). | Use `NSPasteboard.general.changeCount` (no prompt), and on newer systems use `detect(patterns:)` / `accessBehavior` where available. First-run onboarding explains the system prompt and links to *System Settings → Privacy & Security → Paste from Other Apps* (set to **Allow**). Clippy can't bypass it and shouldn't. |
| **Global hotkey** | `RegisterEventHotKey` (Carbon) is still the supported way, works **without** Accessibility permission, and works in the App Store sandbox. `NSEvent.addGlobalMonitor` needs Input Monitoring. | Carbon `RegisterEventHotKey` via a small wrapper. Customisable. |
| **Pasting into the front app** | There is no API to "insert text into another app". Only option: put data on the pasteboard and **synthesize ⌘V** with `CGEvent`. Posting events to other apps requires **Accessibility** permission (`AXIsProcessTrusted`). | Selecting an item always writes it to the pasteboard (that part needs no permission). If Accessibility is granted we also post ⌘V. If not, we degrade gracefully to "Copied — press ⌘V" and show a one-time prompt. |
| **Restoring focus** | Our panel must not steal activation from the target app, otherwise ⌘V goes to us. | Use a non-activating `NSPanel` (`.nonactivatingPanel`, `canBecomeKey = true`). The previous frontmost app stays frontmost; we also remember it and re-activate before pasting as a fallback. |
| **Secure Input** | When a password field is focused, the system enables Secure Event Input; global hotkeys via event taps/monitors stop working, and synthesized key events may be blocked. Carbon hotkeys generally still fire, but paste may not. | Detect `IsSecureEventInputEnabled()`; show a subtle "Secure Input is on — press ⌘V" hint rather than silently failing. |
| **Source app detection** | The pasteboard doesn't say who wrote to it. Best available: `NSWorkspace.frontmostApplication` at the moment we notice the change (can be wrong by ≤0.4 s). macOS 15+/16 also exposes `org.nspasteboard.source`, which some apps set. | Prefer `org.nspasteboard.source` when present, else frontmost app. Labelled best-effort. |
| **Launch at login** | `SMAppService.mainApp` (macOS 13+). Requires the app to live in /Applications for reliability. | Used directly; status shown in Settings. |
| **Menu-bar-only app** | `LSUIElement = true`, `NSStatusItem`. | Done via Info.plist + `NSApp.setActivationPolicy(.accessory)`. |
| **Sandbox / App Store** | Sandbox allows Carbon hotkeys, pasteboard, SMAppService, network client. **Accessibility API (`AXIsProcessTrusted`+CGEvent posting) is effectively incompatible with the sandbox**, so auto-paste can't ship in a sandboxed build. | Ship **Developer-ID notarized, non-sandboxed** as primary distribution (like Maccy/Raycast/Alfred). A sandboxed App Store variant would be copy-only. Hardened Runtime on. |
| **Clipboard from Universal Clipboard / other devices** | Arrives as normal pasteboard changes. | Handled identically. |
| **Password managers** | Most set `org.nspasteboard.ConcealedType` and auto-clear in ~60 s. | Respected by default. |
| **Large / lazy data** | Apps can *promise* data lazily (file promises, huge images). | Cap size on read (default 10 MB per item, 5 MB text), skip file promises. |
| **Sensitive detection can't be perfect** | Heuristics have false negatives. | Be explicit in the UI: "reduces risk, not a guarantee". Fail closed on high-entropy secrets; always offer one-keystroke delete. |

## 3. Feature split

### MVP — v0.1 (reliable clipboard first; **no AI**)
- Clipboard monitor (text, URL, image, file URLs), pause/resume
- 24 h retention (configurable: 1h/6h/12h/24h/3d/7d/never), cleanup worker
- Option+V floating panel (non-activating, centered, translucent)
- Instant in-memory search, arrow keys, Enter to paste, Esc to close
- Pinning (own section, no expiry, encrypted)
- Exact duplicate detection via SHA-256 (bump existing entry)
- Sensitive-content filtering before persistence
- Deterministic categories & filters (All/Text/Code/Links/Images/Files/Pinned)
- Menu bar app, Settings (General/Clipboard/Privacy/AI-stub/Shortcuts/Appearance/About), Launch at Login
- Excluded apps list, disk usage limits, max history size

### v1 — "Clippy AI"
Semantic search (local embeddings via `NLContextualEmbedding`/`NLEmbedding`), smart actions & Cmd+K menu, AI rewrite/summarise/explain (local Apple Foundation Models preferred, cloud opt-in), memory Q&A (retrieval-only, no hallucinated items), similar-item grouping, smart pin suggestions, cleanup intelligence (early-delete only), command mode.

### Future
Snippet expansion (`;sig`), paste-as-plain-text / transform pipelines, OCR on images (Vision) feeding search, Shortcuts/App Intents, iCloud-synced *pinned only* (E2E), Share-sheet capture, per-app paste rules, multi-select merge-paste, URL title/favicon fetch (opt-in), text-in-image redaction.

### Additional genuinely useful ideas (kept small)
1. **Paste as plain text** (`⌥Enter`) — strip formatting. Highest-value tiny feature.
2. **Quick paste ⌘1…⌘9.**
3. **OCR for images** (Vision, local) so screenshots are searchable.
4. **"Copy count" badge** powering pin suggestions.
5. **Transient mode**: ⌥⇧V — "next copy is not recorded".
6. **Per-app rules**: never record from X; always strip formatting for Y.

## 4. Architecture

Swift 6, SwiftUI for UI, AppKit for the panel/menu bar/hotkey/pasteboard. Zero third-party dependencies (SQLite3 is a system library).

```
┌──────────────────────────── App layer ────────────────────────────┐
│ ClippyApp / AppDelegate · MenuBarController · ClippyWindowController│
│ SwiftUI: ClipboardPanelView · SettingsView · ItemRow · PreviewPane  │
└───────────────▲───────────────────────────────────────▲────────────┘
                │ @Observable view models               │
┌───────────────┴──────── Domain / services ─────────────┴───────────┐
│ ClipboardMonitor ─► CapturePipeline ─► ClipboardRepository          │
│   (poll changeCount)   1 filter(app/type hints)                     │
│                        2 SensitiveContentDetector                   │
│                        3 DuplicateDetector (SHA-256)                │
│                        4 Classifier (deterministic)                 │
│                        5 persist + index                            │
│ CleanupService (timer) · SearchEngine · SettingsManager             │
│ GlobalHotkeyManager · PasteManager · SourceApplicationDetector      │
├──────────────────────── Persistence ───────────────────────────────┤
│ ClipboardDatabase (SQLite, WAL) · BlobStore (images/files on disk)  │
│ CryptoBox (AES-GCM, key in Keychain)                                │
├──────────────────────── AI (v1, optional) ─────────────────────────┤
│ protocol AIService { rewrite, summarize, explain, ask }             │
│   LocalAIService (Foundation Models / on-device)                    │
│   CloudAIService (provider protocol; OFF by default)                │
│ protocol EmbeddingProvider → LocalEmbeddingProvider                 │
│ SemanticSearchEngine · SmartActionRegistry · PinSuggester           │
└─────────────────────────────────────────────────────────────────────┘
```

**Why SQLite (via the system `SQLite3` C API) rather than SwiftData/Core Data:** we need `DELETE … WHERE expires_at < ?` on a timer, FTS5, predictable memory and schema control for secure deletion (`PRAGMA secure_delete=ON`). SwiftData adds a macro/runtime layer and weaker control over deletion semantics; it also has a high launch cost for a "must feel instant" utility. A ~200-line wrapper is cheaper than the dependency.

**Hot path:** on panel open, the last N items are already in an in-memory array (kept in sync by the repository), so showing the panel does no I/O. Search filters that array (a few thousand items → sub-millisecond) with a ranking function; FTS5 is the fallback for large histories.

**Concurrency:** Monitor and pipeline run on the main actor for pasteboard access (AppKit requirement) but hash/detect/persist hop to a serial `ClipboardStore` actor. UI state is `@MainActor @Observable`.

## 5. Local database

`~/Library/Application Support/Clippy/clippy.sqlite` (WAL, `secure_delete=ON`, file mode 0600) and `…/Blobs/<uuid>.bin`.

```sql
CREATE TABLE clip_item (
  id            TEXT PRIMARY KEY,          -- UUID
  kind          TEXT NOT NULL,             -- text|url|image|file|…
  category      TEXT NOT NULL,             -- link|code|command|email|phone|json|path|…
  content_hash  TEXT NOT NULL UNIQUE,      -- SHA-256 hex of canonical content
  text          BLOB,                      -- UTF-8 (AES-GCM sealed when pinned)
  preview       TEXT NOT NULL,             -- ≤200 chars, single line
  blob_path     TEXT,                      -- images/files
  thumb_path    TEXT,
  byte_size     INTEGER NOT NULL,
  source_bundle TEXT, source_name TEXT,
  created_at    REAL NOT NULL,             -- first seen
  last_used_at  REAL NOT NULL,             -- bumped on dup / paste
  copy_count    INTEGER NOT NULL DEFAULT 1,
  pinned        INTEGER NOT NULL DEFAULT 0,
  pin_order     INTEGER,
  expires_at    REAL                       -- NULL = never (pinned or retention=never)
);
CREATE INDEX idx_clip_last_used ON clip_item(last_used_at DESC);
CREATE INDEX idx_clip_expires   ON clip_item(expires_at) WHERE pinned = 0;
-- v1 additions
CREATE TABLE clip_embedding (id TEXT PRIMARY KEY REFERENCES clip_item(id) ON DELETE CASCADE, model TEXT, dim INTEGER, vec BLOB);
CREATE VIRTUAL TABLE clip_fts USING fts5(text, preview, content='');
```

**Retention semantics.** `expires_at = created_at + retention`. A duplicate copy *does not* extend `expires_at` of an old item beyond policy: it resets `created_at`/`expires_at` as a **fresh user copy** (the user did copy it again, so it's a new 24 h window) — this is user action, not AI. Changing retention recomputes `expires_at` for unpinned items. Unpinning gives a fresh window.

**Cleanup worker** (every 5 min + on launch + on wake):
```sql
DELETE FROM clip_item WHERE pinned = 0 AND expires_at IS NOT NULL AND expires_at < :now;
```
Then delete orphan blobs, enforce `max_items` (oldest unpinned first) and `max_disk_bytes` (default 500 MB; images evicted oldest-first), then `PRAGMA wal_checkpoint(TRUNCATE)` and occasional `VACUUM`. Blob files are overwritten with zeros before unlink on deletion.

**Images:** stored as PNG/TIFF file blobs, downscaled thumbnail (≤256 px) for the list; per-item cap 10 MB; images count toward the disk budget.

## 6. Privacy & security model

**Principles:** local-only by default · detect *before* persist · fail closed · short retention · minimal data · no logging of content.

### Sensitive-content detector (runs before anything touches disk)
Order = cheapest and most reliable first; first hit short-circuits.

1. **Pasteboard hints** (most reliable): `org.nspasteboard.ConcealedType`, `org.nspasteboard.TransientType`, `org.nspasteboard.AutoGeneratedType`, `com.agilebits.onepassword`, `de.petermaurer.TransientPasteboardType`. → ignore.
2. **Source-app denylist**: 1Password, Bitwarden, KeePassXC, Dashlane, LastPass, Keychain Access, Apple Passwords (by bundle ID), plus user-added.
3. **Structural regexes (high precision)**
   - PEM/SSH private keys (`-----BEGIN … PRIVATE KEY-----`, `OPENSSH PRIVATE KEY`)
   - AWS access key `\b(AKIA|ASIA)[0-9A-Z]{16}\b`; AWS secret (40 base64 chars near `aws`/`secret`)
   - GitHub `gh[pousr]_[A-Za-z0-9]{36,}`, `github_pat_…`; GitLab `glpat-`; Slack `xox[abprs]-`; Stripe `sk_live_|rk_live_`; Google `AIza[0-9A-Za-z_-]{35}`; OpenAI/Anthropic `sk-…`, `sk-ant-…`; npm `npm_…`; Twilio, SendGrid `SG\.…`
   - JWT `eyJ…\.eyJ…\.…` (3 base64url segments, header decodes to JSON)
   - `Authorization: Bearer …`, `Cookie:`/`Set-Cookie:` with session-like names, `password=`/`secret=`/`token=`/`api_key=` assignments, DB URLs with embedded creds (`scheme://user:pass@`)
4. **Credit cards**: 13–19 digits (spaces/dashes allowed) that pass **Luhn** and a known IIN range. Luhn eliminates most false positives.
5. **OTP / 2FA codes**: whole clipboard is 4–8 digits (or `123-456`) **and** (source app is a messages/auth/mail app, or the copy is within seconds of a notification-ish app). Bare 6-digit numbers from arbitrary apps are *dropped by default* too (cheap to re-copy, costly if wrong) — configurable.
6. **Seed phrases**: 12/15/18/21/24 lowercase words, all in the BIP-39 wordlist (bundled, 2048 words; ≥ 90 % match for tolerance).
7. **Entropy heuristic** (catch-all): for a *single token* (no whitespace, 20–256 chars) compute Shannon entropy per char and character-class mix; flag if entropy ≥ 4.0 bits/char (hex ≥ 3.5, base64 ≥ 4.5) with ≥ 3 classes and not a URL/path/UUID/git-SHA/known-benign pattern. Allowlist: UUIDs, git hashes (40 hex are *ambiguous*; treated as benign unless nearby key context), plain URLs without credentials, file paths.
8. **Context**: if text contains `password`, `passwd`, `secret`, `token` etc. adjacent to a high-entropy token on the same line → flag.

**Outcome modes** (setting *Protect Sensitive Clipboard Data*, on by default):
- **Drop** (default) — never stored, never indexed, never embedded, never sent to AI.
- **Memory-only** — kept ≤ 60 s in a RAM-only list, marked 🔒, shown once; zeroed on expiry.
Also: sensitive items are *never* eligible for AI processing, cloud or local, and can't be pinned without a confirm.

**Testing:** a table-driven unit-test corpus of positive and negative samples (real-format fake keys, benign hashes, UUIDs, lorem ipsum, code snippets) with the detector measured for precision/recall; every false-negative bug becomes a regression case.

### Storage security
- DB and blobs are in the app container dir, perms `0600/0700`, excluded from Time Machine (`isExcludedFromBackup`), `secure_delete`.
- **Pinned** item bodies are sealed with AES-256-GCM (CryptoKit); the key is generated once and stored in the macOS Keychain (`kSecAttrAccessibleWhenUnlockedThisDeviceOnly`). Unpinned items are short-lived and plain, to keep search instant and cleanup cheap (explicit trade-off, documented).
- No analytics, no telemetry, no network calls unless the user enables cloud AI.
- Logs never contain clipboard content (only counts/hashes/types).
- Hardened Runtime; no `get-task-allow` in release.

### AI privacy
- Cloud AI: **off**, requires master toggle + "Allow cloud processing" + API key (Keychain). Each cloud action shows what will be sent; only the user-selected item is sent, never history.
- Memory Q&A is *retrieval-only*: the model gets top-K local hits and must answer with IDs from that set; no hit ⇒ the app (not the model) prints "No matching clipboard item found."

## 7. User experience

- **Option+V** → panel appears in <50 ms at ~⅓ from the top of the active screen, 640×460, `NSVisualEffectView` (`.hudWindow`/`.popover` material), 16 pt radius, soft shadow. Search field auto-focused.
- Layout: search field · filter chips (All, Text, Code, Links, Images, Files, Pinned) · list (Pinned section on top, then Today/Yesterday) · optional preview pane for the selected item · footer with key hints (`↩ Paste  ⌘K Actions  ⌘P Pin  esc Close`).
- **Keys:** ↑/↓ move · ↩ paste · ⌥↩ paste plain · ⌘↩ copy only · ⌘P pin · ⌘⌫ delete · ⌘1–9 quick paste · Tab/←→ cycle filters · ⌘K actions · esc close (first esc clears search).
- **Rows:** type glyph (SF Symbol), single-line preview (monospaced for code), source-app icon, relative time ("2m"), pin dot. Images show a thumbnail.
- **Animations:** 120 ms fade+scale (0.98→1) on appear; selection highlight without animation; no springs.
- **Menu bar:** template icon; menu per spec (Open, History submenu with last 10, Pinned submenu, Clear History, Pause, Settings…, Quit).
- **Settings:** native `Settings`-style window with `TabView` (General, Clipboard, Privacy, AI, Shortcuts, Appearance, About).
- **Onboarding (first run):** one sheet: what's captured, 24 h promise, how to grant Accessibility (for auto paste) and Paste-from-Other-Apps, how to set the hotkey.
- **Appearance:** System/Light/Dark via `NSApp.appearance`. Dark mode is the reference design.

## 11. AI implementation notes (as built)

- **Local first.** Apple’s on-device model (FoundationModels) for text tasks; `NLEmbedding` sentence vectors for similarity. Cloud sits behind a `CloudProvider` protocol (Anthropic implemented) and is gated by *Enable AI* + *Allow cloud processing* + a Keychain key, re-checked on every call.
- **Embeddings measured, not assumed.** Raw `NLEmbedding` ranked only ~4/8 test queries correctly (chatty text outranked terse commands). Embedding a *category-prefixed* description (“terminal command: …”, URLs split into words) helped materially, and hybrid retrieval (intent + keywords + embeddings) got 5/5 on the test set with 0 hits for unrelated queries. Embedding-only admission needs cosine ≥ 0.62 to avoid false matches.
- **No hallucinated items.** Retrieval is deterministic; the LLM may only re-order the top candidates by number. “No matching clipboard item found.” is produced by the app.
- **Pinned items.** Their vectors are kept in memory only (never written to disk), consistent with encrypting pinned content at rest.
- **Guarding AI input.** `AIGuard` re-runs the sensitive detector right before any model call; held-sensitive items are never embedded or sent.
- **Retention invariant.** Junk cleanup, pin suggestions and AI results cannot extend `expires_at`; a re-copy by the user is the only thing that starts a new window.
